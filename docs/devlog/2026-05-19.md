# 2026-05-19

The introduction of the programme schema triggered a perspective shift on the window organisation and general architecture of the desktop client.

The usage lifecycle is modelled as follows:

1. The desktop client is used to compose a programme and saves the configuration to disk.
2. Once the Pico is connected, the desktop client is used to load the programme to the Pico.
3. The desktop client is used to begin the programme on the Pico.
4. The Pico, provided it has its own power supply, can be safely disconnected from the desktop client.
5. The Pico stores all sensor readings and control loop outputs to disk.
6. If the desktop client is connected during the execution of the programme, a live monitor is displayed; if not, then the desktop client shows a history of the programme during its execution.

To begin scaffolding the document management aspect, we began by creating a simple YAML editor to test the document lifecycle.

We planned a 3 panel layout for the editor:

- The left hand side panel lists the blocks in the programme. Clicking any of the list items jumps to a single cycle of the block. Blocks can be added and removed from this panel too.
- The central panel features the preview of the programme, all of its samples from all of its blocks. This represents the final target pressure profile of the programme.
- The right hand side panel is an inspector panel where properties about the programme and specific blocks can be changed.

Some extra features planned include:

- Full document app feature set (New, Open, Save, Save As) in the menu bar along with appropriate keyboard shortcuts.
- Keyboard shortcuts for quickly adding and removing blocks, as well as zooming to fit.
- A console window that opens during simulation to display logs from the simulation subprocess.
